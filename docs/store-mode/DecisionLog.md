# Mağaza rejimi — Decision Log

SRS (bölmə 25) tələb edir: qeyri-müəyyən məsələlərdə özbaşına biznes davranışı seçilməsin, təklif olunan standart, risk və təsir yazılsın. Aşağıdakı qərarlar hazırda **təklif edilmiş standartdır**; təsdiq və ya dəyişiklik gözləyir.

| # | Məsələ | Seçilmiş standart | Risk | Təsir (dəyişsə) |
|---|--------|-------------------|------|-----------------|
| 1 | Rejimin ayrılması | Restoran POS-undan ayrı: `/store` və `/api/store`, ayrı entity-lər (`Store*`). Şirkət üçün rejim `moduleDataSecimi` ilə açılır. | Restoran və mağaza məhsul kataloqu ümumi deyil (təkrar daxiletmə). | Ümumi kataloq istənərsə məhsul miqrasiyası lazımdır. |
| 2 | Maya dəyəri | Orta çəkili maya (Weighted Average). Satış sətrində snapshot. | Mühasibat FIFO istəyə bilər. | FIFO üçün partiya (lot) cədvəli və maya hesablama dəyişikliyi. |
| 3 | Qiymətlər ƏDV-ni daxil edir | Satış qiyməti ƏDV daxildir; alış qiyməti ƏDV-siz. ƏDV satış sətrində ayrıca hesablanır. | Qanuni hesabat formatı fərqli ola bilər. | Qiymət sahələrinin mənası dəyişər. |
| 4 | Mənfi stok | Şirkət parametri, standart: **qadağan**. | Oflayn satışda qalıq köhnə ola bilər; server sinxronda rədd edə bilər (Conflict). | `AllowNegativeStock=true` etsək oflayn satışlar həmişə keçər, stok mənfiyə düşə bilər. |
| 5 | Oflayn saxlama | Brauzer: növbə `localStorage`, kataloq surəti `IndexedDB`. Ayrıca SQLite/desktop agent **yoxdur**. | Brauzer məlumatı silinərsə, göndərilməmiş satışlar itər. Növbə yalnız satışı əhatə edir. | Desktop (Electron/Tauri+SQLite) agent lazım olsa ayrıca iş. |
| 6 | Oflayn hesabı/token | Oflayn rejimdə mövcud JWT ilə işləyir; token vaxtı bitərsə yenidən giriş (internet) lazımdır. | Uzun oflayn dövrdə sessiya bitə bilər. | Oflayn PIN/token strategiyası ayrıca dizayn. |
| 7 | Sinxron konflikti | Stok/serial çatışmazlığı `Conflict`, digər rədd `Failed`; hər ikisi növbədə və serverdə (`StoreSyncOperations`) səbəblə qalır, bildiriş göndərilir. Avtomatik həll yoxdur — insan qərar verir. | Kassir konfliktlə qarşılaşana qədər müştəri getmiş olur. | Avtomatik "mənfi stoka icazə ver" siyasəti əlavə edilə bilər. |
| 8 | Menecer təsdiqi | Menecerin istifadəçi adı+parolu serverdə yoxlanır, təsdiq edən ≠ kassir. Oflayn növbəyə təsdiq/parol yazılmır. | Oflayn satış təsdiq tələb edən addımdadırsa, sinxronda rədd olunur. | Oflayn təsdiq üçün imzalı vaxtlı kod mexanizmi. |
| 9 | Fiskal cihaz | Yalnız `IStoreFiscalDevice` interfeysi + "konfiqurasiya edilməyib" adapter. Satış fiskal xəta olsa da qüvvədədir (status `Failed`, yenidən göndərmə var). | Qanunla fiskal çek məcburidirsə, adapter olmadan istehsalda istifadə olmaz. | Cihaz modeli/protokolu məlum olandan sonra adapter yazılır. |
| 10 | Çek printeri/tərəzi/bank terminalı | Printer: brauzer çapı (ölçü/şablon hələ sabit). Tərəzi: yalnız çəki kodlu barkod (`2`+5 rəqəm məhsul kodu+5 rəqəm çəki qramla+nəzarət) və əl ilə daxiletmə. Bank terminalı inteqrasiyası **yoxdur** (kart ödənişi əl ilə təsdiq). | Hər mağazanın barkod formatı fərqli ola bilər. | Prefiks/uzunluq parametrləşdirilir. |
| 11 | Bonus | 1 bonus = 1 AZN; faiz həqiqətən ödənilən məbləğdən (bonus/borc istisna); istifadə limiti faizlə; müddət gün ilə (0 = sonsuz), köhnədən istifadə (FIFO); məhsul səviyyəsində "bonus qazandırır" bayrağı. Müddət bitməsi balansa baxılan/istifadə olunan anda yazılır (arxa plan işi yoxdur). | Siyahıda balans, müştəriyə baxılana qədər müddəti bitmiş bonusu hələ göstərə bilər. | Gecə işi (hosted service) əlavə edilə bilər. |
| 12 | Borca satış | İcazə + müştəri kredit limiti məcburidir; limit 0-dırsa borca satış olmur. | — | — |
| 13 | Çeksiz satış | Ayrıca rejim yoxdur: hər satışın sənəd nömrəsi var, çapı istəyə bağlıdır. | Qanun çeksiz satışı fərqli tələb edə bilər. | Çeksiz satış bayrağı və icazəsi əlavə edilə bilər. |
| 14 | Filial/anbar məhdudiyyəti | Kassa → anbar+filial; sorğularda şirkət məhdudiyyəti server tərəfdə. İstifadəçi→filial məhdudiyyəti var (sətir yoxdursa məhdudiyyət yoxdur); anbar məhdudiyyəti filialın anbarları vasitəsilədir. | Filial istifadəçisi şirkətin digər filial məlumatını icazə olduqca görə bilər. | Filial üzrə məhdudiyyət filtr + permission dəyişikliyi. |
| 15 | Audit | Mağaza əmrləri (`*Command`) uğurlu olduqda avtomatik ümumi audit jurnalına yazılır (parol/təsdiq çıxarılır). Köhnə dəyər (before) ümumi yazılmır, yalnız sorğu (after). | Köhnə/yeni dəyər müqayisəsi tam deyil. | Əsas entity-lər üçün before/after snapshot. |
| 16 | API versiyası | `/api/store/...` versiyasız. | Sonrakı pozucu dəyişiklik köhnə clientləri sındırar. | `/api/v1/` marşrutlaşdırma. |
| 17 | Dil | Mağaza UI Azərbaycan dilində yazılıb; İngilis dili lüğət əsasında ekranda yerində dəyişdirilir (AZ/EN düyməsi). | Lüğətdə olmayan mətn (server xətası, dinamik cümlə, çek) tərcümə olunmur; real i18n qatı deyil. | Tam i18n üçün mətnlər açar əsaslı tərcümə qatına köçürülür. |
